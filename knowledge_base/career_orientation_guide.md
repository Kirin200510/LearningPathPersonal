# Hướng dẫn chọn hướng nghề nghiệp IT


> Tài liệu này dùng để định hướng học tập và xây dựng lộ trình cá nhân hóa. 
> Nó không phải cam kết về tuyển dụng, mức lương hoặc thời gian chắc chắn để có việc.


## Không nên chọn nghề chỉ theo tên công nghệ

Framework và công cụ thay đổi, nhưng loại vấn đề bạn thích giải quyết thường ổn định hơn. Hãy chọn hướng dựa trên loại công việc, cách tư duy và môi trường bạn muốn trải nghiệm.

## Bảng định hướng nhanh

| Bạn thường thích | Hướng nên khám phá |
|---|---|
| Logic nghiệp vụ, API và database | Backend Developer |
| Giao diện và trải nghiệm tương tác | Frontend Developer |
| Ứng dụng chạy trên điện thoại | Mobile Developer |
| Phân tích số liệu và báo cáo | Data Analyst |
| Pipeline, kho dữ liệu và hệ thống | Data Engineer |
| Thống kê, mô hình và khám phá dữ liệu | Data Scientist |
| Triển khai mô hình thành dịch vụ | Machine Learning Engineer |
| Hệ thống, tự động hóa và vận hành | DevOps/Cloud Engineer |
| Điều tra rủi ro và bảo vệ hệ thống | Cybersecurity Analyst |
| Tìm lỗi, thiết kế test và chất lượng | QA/Test Engineer |
| Xây sản phẩm phần mềm tổng quát | Software Engineer |

## Câu hỏi chatbot nên hỏi sinh viên

1. Bạn đã học ngôn ngữ lập trình nào và tự đánh giá mức độ bao nhiêu?
2. Bạn thích kết quả trực quan hay logic phía sau hệ thống?
3. Bạn thích làm việc với dữ liệu, giao diện, hạ tầng hay bảo mật?
4. Bạn có hứng thú với toán và thống kê không?
5. Bạn muốn xây sản phẩm, phân tích, vận hành hay kiểm tra chất lượng?
6. Bạn có bao nhiêu giờ học mỗi tuần?
7. Bạn đã hoàn thành dự án nào?
8. Bạn muốn thực tập trong khoảng thời gian nào?
9. Bạn thích làm cá nhân hay phối hợp nhiều vai trò?
10. Bạn có máy đủ tài nguyên cho mobile, data hoặc AI không?

## Quy tắc gợi ý hướng nghề

Không đưa ra kết luận chỉ từ một câu trả lời. Chatbot nên đề xuất từ hai đến ba hướng gần nhất, nêu lý do, điểm còn thiếu và một bài thử nhỏ cho mỗi hướng.

Ví dụ, sinh viên thích Python, database và xây API có thể được đề xuất Backend Developer. Nếu đồng thời thích pipeline và xử lý dữ liệu, Data Engineer là lựa chọn thứ hai để so sánh.

## Bài thử định hướng trong 7 ngày

### Backend

Xây API CRUD nhỏ có database và validation.

### Frontend

Dựng giao diện responsive và gọi một API công khai.

### Mobile

Xây ứng dụng hai màn hình, lưu dữ liệu cục bộ.

### Data Analyst

Phân tích một file dữ liệu và trình bày ba phát hiện.

### Data Engineer

Viết pipeline lấy dữ liệu API, làm sạch và nạp database.

### Data Science

Xây baseline cho một bài toán dự đoán và đánh giá metric.

### ML Engineer

Đóng gói một model mẫu thành API có Docker.

### DevOps

Container hóa ứng dụng và tạo pipeline test tự động.

### Cybersecurity

Xây lab hợp pháp, phân tích log và viết báo cáo rủi ro.

### QA

Viết test plan, test case và bug report cho một ứng dụng.

## Cách đánh giá sau bài thử

Chấm theo bốn tiêu chí từ 1 đến 5:

- Mức độ hứng thú trong quá trình làm.
- Khả năng tập trung khi gặp lỗi.
- Mong muốn học sâu hơn.
- Mức độ phù hợp với nền tảng hiện tại.

Điểm cao không có nghĩa phải chọn ngay. Nó chỉ giúp thu hẹp lựa chọn và thiết kế lộ trình thử nghiệm tiếp theo.

## Nguyên tắc cá nhân hóa lộ trình

1. Tôn trọng kỹ năng đã có, không bắt học lại toàn bộ.
2. Bổ sung prerequisite trước môn nâng cao.
3. Giới hạn khối lượng theo số giờ mỗi tuần.
4. Mỗi giai đoạn phải tạo ra sản phẩm hoặc bằng chứng học tập.
5. Đánh giá lại sau mỗi dự án.
6. Cho phép đổi hướng mà vẫn tận dụng kỹ năng chung.
